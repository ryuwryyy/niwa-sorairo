# Part 1 — デザイン思考：何を作るかを決める

## 1.1 5段階を、この事業で実際に何をやったかに対応させる

デザイン思考は手順であって呪文ではない。各段階の**アウトプットが何だったか**を明示する。

| 段階 | やったこと | アウトプット | 検証状態 |
|---|---|---|---|
| **共感** Empathize | 購入済み・検討中のデプス調査 | 「住民ガチャが怖い」「中立意見ではない」という生の言葉 | n=数名。**不足** |
| **定義** Define | 課題の再定義 | **「内見は、晴れた日曜の昼しか見せてくれない」** | 第三者調査（後悔1位ご近所・2位騒音）と一致 |
| **発想** Ideate | 解の探索と棄却 | 代理指標（管理規律を読む）。UGC口コミ・AIレポート・建物診断を棄却 | 論理的には成立 |
| **試作** Prototype | コンシェルジュMVP | 手作業のレポート5件 | **未実施** |
| **検証** Test | GATE 1 | 10件提示 → 5件入金 | **未実施** |

> **重要**：共感が n=数名で止まっているのに、定義以降を積み上げている。
> これは弱点である。**デッキでも隠さない。**

## 1.2 定義（Define）の書き方 — POVステートメント

デザイン思考で最も重要な工程は「定義」である。ここを曖昧にすると、以降の全てがぼやける。

**Point of View ステートメント**（ユーザー／ニーズ／洞察の3点で固定する）

> **候補を1〜2件に絞ったが決めきれない共働き夫婦は、**
> **「隣に誰が住んでいるか」を知る手段を必要としている。**
> **なぜなら、法律は買主に自衛を求めているのに、自衛の手段が市場に売られていないからだ。**

この3行から、以下がすべて導かれる。

- 商品（現地実測）
- 価格（法的自衛手段としての価格。便利サービスの価格ではない）
- トーン（不安を煽らない。淡々と測る）
- ビジュアル（実測値が主役。感情は顧客のもの）

## 1.3 「どうすれば〜できるか（HMW）」の設定

発想を縛るために、問いの形を固定する。

| ❌ 悪い問い | ⭕ 良い問い |
|---|---|
| どうすれば住民の情報を集められるか | **どうすれば個人を調べずに、隣人への不安を解けるか** |
| どうすれば安くレポートを作れるか | **どうすれば現地に行く時間を削らずに、それ以外を削れるか** |
| どうすれば信用されるか | **どうすれば「買うな」と言えることを、証明として見せられるか** |

> 良い問いは**制約を含んでいる**。制約のない問いは、凡庸な答えしか生まない。
> 「個人を調べずに」という制約が、代理指標という発明を生んだ。

# Part 2 — クリエイティブディレクション：何を言うかを決める

## 2.1 コアアイデア

> **測ることが、唯一の誠実さである。**

この事業のすべての判断を、この一行で裁定する。
迷ったら「それは測っているか／測った結果を歪めていないか」を問う。

## 2.2 中心にある緊張（Central Tension）

優れたクリエイティブには、必ず緊張がある。この事業の緊張はこれだ。

> **極めて感情的な問題（家を買う不安）を、極めて非感情的な手段（実測値）で扱う。**

この緊張を壊してはいけない。

| 緊張を壊す表現 | なぜダメか |
|---|---|
| 「安心してお任せください」 | 感情を感情で扱っている。競合と同じになる |
| 「知らずに買うと後悔します」 | 不安商法。信頼を失う最短路 |
| 「AIが最適な住まいを提案」 | 測っていない。コアアイデアに反する |

**正しい扱い方：感情は顧客のもの。我々の言葉は数字である。**

## 2.3 メッセージ構造（Message Architecture）

ピラミッドで固定する。下位は上位を支え、上位と矛盾しない。

```
                  【マスターメッセージ】
        内見は、晴れた日曜の昼しか見せてくれない。
                          │
        ┌─────────────────┼─────────────────┐
     【柱1】            【柱2】            【柱3】
   我々は行く。        人を調べない。      買うなと言える。
   平日の夜、朝、      掲示板を読む。      報酬が成約に
   そして雨の日に。                        連動していない。
        │                  │                  │
   実測値・時刻・      管理規律という      全レポートに
   天候を記録する      代理指標           やめるべき3つの理由
```

### マスターメッセージが強い理由（採用基準の実例）

| 基準 | 「内見は、晴れた日曜の昼しか見せてくれない」 |
|---|---|
| 全員が経験しているか | ◯ 内見に行った人は全員そうだった |
| 誰かを悪者にしていないか | ◯ 不動産会社を責めていない。事実を述べただけ |
| 次の問いが自動的に立つか | ◯「では他の時間は？」 |
| 商品説明がそのまま続くか | ◯「だから我々は平日の夜に行きます」 |
| 競合が同じことを言えるか | ✕ 言えば自分の営業を否定することになる |

> **5つ全部を満たすコピーだけを採用する。** 4つでは足りない。

## 2.4 トーン・オブ・ボイス

**人格設定：冷静な測定者**

熱心な営業でも、優しい相談相手でもない。**測って、記録して、そのまま渡す人**。

| する | しない |
|---|---|
| 事実を、静かに、数字で置く | 恐怖を増幅する |
| 「問題ありませんでした」も同じ重さで語る | 失敗談で煽る |
| 分からないことは「分かりません」と書く | 断定・保証する |
| 顧客の判断力を信頼する | 「素人には無理です」と言う |
| 自分の間違いを訂正する | 都合の悪い数字を隠す |

**語尾の規則**：断定は事実にのみ使う。推定には必ず「推定」と書く。
**一人称**：「私たち」。専門家ぶった「弊社」は使わない。

# Part 3 — アートディレクション：どう見せるかを決める

## 3.1 ビジュアルコンセプト

> **調査野帳（フィールドノート）**

測量士や現地調査員が持つ野帳。方眼、日付、天候、実測値、署名。
不動産広告の対極——艶やかな写真、青空、家族の笑顔——ではなく、**記録の美学**を採る。

この選択の根拠は装飾ではない。**商品そのものが「記録」だから**である。
ビジュアルコンセプトは、商品の材料から導く。思いつきで選ばない。

## 3.2 グリッド — 方眼を下敷きにする

**すべての要素が方眼にスナップする。**

- 基準単位：**8px**（すべての余白・サイズは8の倍数）
- 背景に方眼（32px）を極薄で敷く。これが「測る」という概念の視覚化
- 本文の折り返しは **65文字前後**
- スライドの左右マージンは**最低32px**、スマートフォンでは16px

> 方眼は飾りではない。**「この会社は、すべてを測っている」という態度の表明**である。

## 3.3 タイポグラフィ — 3つの役割を分ける

| 役割 | 書体 | 使いどころ | 規則 |
|---|---|---|---|
| **表題** | Zen Kaku Gothic New 900 | 見出し | 図面注記のような硬質さ。行間1.34、`text-wrap: balance` |
| **本文** | Noto Sans JP 400/700 | 文章 | 行間1.75。1行65文字まで |
| **実測** | JetBrains Mono 400/700 | **数値・時刻・単位・ラベル** | **数字は必ず等幅。例外なし** |

### タイプスケール（8pxグリッドに乗せる）

| 用途 | サイズ | ウェイト |
|---|---|---|
| 表紙 | 74px | 900 |
| 章見出し | 34px | 900 |
| 小見出し | 15px | 700 |
| 本文 | 15px | 400 |
| 補足 | 12.5px | 400 |
| ラベル | 10.5px | 500／字間 .18em／大文字 |

> **鉄則：数値をゴシック体で組まない。**
> 58.4 dB は等幅で組まれて初めて「実測値」に見える。

## 3.4 カラー — 比率を先に決める

| 役割 | 色 | 使用比率 |
|---|---|---|
| 地（野帳の紙） | わずかに緑みのオフホワイト | **90%** |
| 主線・文字 | 黒に近い藍 | — |
| **アクセント（測量オレンジ）** | 測量ポール・マーキングの色 | **7%** |
| 副（製図の青緑） | データ・肯定 | **3%** |
| 棄却（朱） | 棄却・警告のみ | 極小 |

**規則**
1. **1画面にアクセントは1箇所だけ。** 2箇所以上あるときは、どちらかが不要
2. 棄却色は「棄却」と「危険」にしか使わない。目立たせたいから赤、は禁止
3. **グラフの配色は自動検証を通す**（色覚多様性・コントラスト・彩度・明度帯）
4. 明暗どちらのテーマでも同じ意味に見えること

## 3.5 モチーフ — ブランドの「顔」を1つ決める

> **実測ラベル**　`58.4 dB / 21:40 / 曇`

値・時刻・天候の3点セット。これを全メディアで繰り返す。

**なぜこれが強いか：他社は真似できない。測っていないからだ。**

補助モチーフ：
- **測点マーク**（十字のレジストレーション）— 章の区切りに
- **打ち消し線** — 棄却した仮説に。訂正の履歴を見せることが信頼になる

## 3.6 写真・図版の規則

| する | しない |
|---|---|
| 夕方・夜・雨天 | **晴れた休日の昼**（これを使わないこと自体がメッセージ） |
| 掲示板、ゴミ集積所、共用廊下 | 青空の新築外観 |
| 実測値を重ねる | 人物の顔（個人を扱わない思想と一致させる） |
| 図は機構を描く | 装飾のためのイラスト |

## 3.7 禁止事項（AD審査基準）

制作物は公開前に全項目を確認する。

- ❌ 家族の笑顔／青空／「理想の住まい」的な語彙
- ❌ グラデーション、過度な角丸、影の多用
- ❌ 絵文字を見出しや章番号に使う
- ❌ 数値をゴシック体で組む
- ❌ 二重軸グラフ（**最も多い誤り**）
- ❌ 色だけで意味を伝える（必ず直接ラベルを併記）
- ❌ 実測していない数値を、実測のように見せる
- ❌ 出典のない数字

# Part 4 — スライドの型（これが「具体的」の核心）

**8つの型だけを使う。** 型を混ぜない。1枚1型。

| # | 型 | 用途 | 構成 | 密度 |
|---|---|---|---|---|
| **1** | **宣言** Statement | 主張を置く | 1文＋大きな余白。数字を入れない | 低 |
| **2** | **数字** Figure | 事実を1つ突きつける | 巨大な数値1つ＋単位＋出典。説明は3行以内 | 低 |
| **3** | **対比** Contrast | 通説を壊す | 2カラム。左＝通説（灰）／右＝事実（黒＋アクセント） | 中 |
| **4** | **検算** Calculation | 論理を追わせる | 計算式をそのまま縦に並べ、最終行だけ色を変える | 中 |
| **5** | **図解** Diagram | 機構を見せる | 図が主役。文章は figcaption のみ | 中 |
| **6** | **台帳** Ledger | 網羅する | 表。**必ず判定列を持つ**（採用／棄却／要確認） | 高 |
| **7** | **棄却** Rejection | 自分の誤りを見せる | 打ち消し線＋判定スタンプ | 中 |
| **8** | **転換** Turn | 幕を変える | **黒地。1行だけ。** 呼吸をつくる | 最低 |

## 4.1 リズム設計 — 密度を一定にしない

**優れたデッキは、密度が波打つ。**

```
密度  高 │      ▄▄        ▄▄▄▄       ▄▄▄
         │    ▄▄  ▄▄    ▄▄    ▄▄   ▄▄   ▄
      低 │ ▄▄        ▄▄            ▄
         └────────────────────────────────
           宣言 数字 対比 検算 転換 図解 台帳 …
```

規則：
1. **台帳（密度・高）の直後には、宣言か転換（密度・低）を置く**
2. **幕の切り替えには必ず黒地の転換スライドを入れる**。読み手に息をさせる
3. 同じ型を3枚続けない

## 4.2 1枚のスライドの構造（テンプレート）

```
┌──────────────────────────────────────┐
│ 01 ／ 章タイトル ───────────────────  │ ← ラベル（mono・アクセント色・字間広め）
│                                      │
│ 大見出しは2行まで。                    │ ← 表題（900・balance）
│                                      │
│ 補助文は1段落。ここで前提を置く。         │ ← 本文（65文字・灰）
│                                      │
│ ┏━━━━━━━━━━━━━━━━━━━━━━━━┓  │
│ ┃  主役（数字／図／表）              ┃  │ ← 1枚に主役は1つだけ
│ ┗━━━━━━━━━━━━━━━━━━━━━━━━┛  │
│                                      │
│ ▎結論を1行で。                        │ ← 罫線付きの断定（任意）
│ ┄ 注記・出典 ┄┄┄┄┄┄┄┄┄┄┄┄┄┄  │ ← 破線の上に小さく
└──────────────────────────────────────┘
```

**鉄則：1枚に主役は1つ。** 図と表を同じ枚に置かない。置きたくなったら2枚に割る。

## 4.3 情報設計の規則

| 規則 | 理由 |
|---|---|
| 結論を先に置く | 読み手は最後まで読まない |
| 表には必ず**判定列**を持たせる | 事実の羅列は何も言っていないのと同じ |
| 出典は各数字の直下に、小さく | 後注にすると誰も照合しない |
| 未確定は**未確定と書く** | これが最大の差別化。誠実さは視覚的に見える |
| 棄却した仮説を残す | 判断の履歴が信頼を作る |

# Part 5 — 適用チェックリスト

制作物を出す前に、全項目を確認する。**1つでも×があれば出さない。**

### 概念
- [ ] POVステートメントの3行に反していないか
- [ ] コアアイデア（測ることが唯一の誠実さ）に反していないか

- [ ] マスターメッセージと矛盾していないか

- [ ] すべての数字に出典があるか
