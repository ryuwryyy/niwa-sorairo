## 1. 何が空いているか

2026年時点で、自然言語からワークフローを生成する機能は既にある
（Zapier Copilot、Make の Maia、n8n の AIノード群）。
だから「自然言語でワークフローが組める」だけでは差にならない。

空いているのはここ。

> **Zapier も Claude Code も「何を自動化するか」は人間が持ち込む前提で立っている。**
> Claude Code は「このバグを直して」と言われて初めて動き、
> Zapier は「このZapを作る」と決めた人がいて初めて動く。
> **「そもそも自分の仕事のどれが自動化できるのか」に答えるものが無い。**

これが対象ピックアップであり、Litron Builder の中心機能。

## 2. 素朴な設計はなぜ失敗するか

```
行動ログ → 反復を検知 → 「7回やってますね、自動化しませんか」
```

これは task mining が既にやっていて、**失敗が知られている**。
RPA の候補選定の定石は「例外がほとんど無い処理を探せ」。
逆に言えば、反復して**見える**だけで例外を含む作業を拾うと自動化は壊れる。
「RPAは死んだ」と言われた原因はほぼこれ。

**頻度は判定軸として弱い。** 7回やった事実は、その7回が同じ経路だったかを何も言っていない。

## 3. 4つのゲート

| ゲート | 測るもの | 効き方 |
|---|---|---|
| **G1 反復性** | 頻度 × 所要時間 = 回収可能時間 | 合否ではなく「やる価値」の目安 |
| **G2 ばらつき** | 例外率 = 主経路から外れた回数 / N | **不採用にしない。モードを割り当てる** |
| **G3 検証可能性** | 機械判定 > 突合 > 抽査 > 受領確認 | **通らないものは候補にしない** |
| **G4 可逆性** | 不可逆ステップ数 | 「危険か」でなく「戻せるか」で分ける |

### G2 がこの設計の肝

RPA は例外の多い作業を捨てるしかなかった。エージェントは判断ができるので、
**例外率でモードを割り当てる**。

| 例外率 | モード | 例 |
|---|---|---|
| 〜10% | **決定論** | 定型レポート生成、定期集計 |
| 10〜40% | **エージェント** | 問い合わせの一次振り分け |
| 40%〜 | **下書き** | 議事録、メール下書き、日報 |

> **今の Push 型（議事録・メール下書き）は、この表の一番下だけをやっている状態。**
> 拡張の方向は「下書きを増やす」ではなく、**例外率の低い側へ登ること**。
> 同じ仕組みで上2段が取れる。これが拡張のオーダーへの回答。

### G3 は通さない側のゲート

検証手段が定義できない作業を自動化すると「やったが、できていない」が静かに溜まる。
Anthropic が検証ループを最重要（品質が2〜3倍変わる）と言っているのと同じ理由。
**落とした候補と、落とした理由も画面に出す。**

## 4. Push と Pull を分けない

```
Push  観測ログ ─┐
                ├→ 【型】 → 検証 → 接続 → 委任 → 運用 → 振り返り
Pull  自然言語 ─┘
```

入口が違うだけで、下流は完全に共通。**統合UIとはこの合流のこと**で、画面を2つ並べることではない。
色でも区別する（Push = 紫 / Pull = 青）。

**Pull で書いたからといって審査を緩めない。** G3 と G4 は同じように課す。
緩めると「Pull で書けば通る」という抜け道ができる。

## 7. 観測とプライバシー

task mining はデスクトップ操作の記録が前提で、各ベンダが明示的な同意と匿名化を要求している。
UiPath は「データ主体への告知は顧客の責任で、我々には同意を取る技術的手段が無い」とまで書いている。
ここは法務対応ではなく**受け入れられるかの分かれ目**なので、製品仕様として先に決めた。

- 観測範囲は本人が選ぶ。既定はオフ。ツール単位でオン
- 観測しているものを**常にサイドバーに出す**
- 生ログは候補化したら捨てる。残すのは型と根拠の要約のみ
- 他人の画面は観測しない

## 8. 正直な制約

- **プロトタイプであり、実装ではない。** 4ゲートの閾値（10% / 40% / 80%）は仮置きで、
  実データでの調整が要る
- **G3の視覚採点は揺れる。** G1/G2 を機械判定にしてあるのは揺れを最小化するため
- **観測基盤は設計のみで、画面は未実装。** [docs/OBSERVATION.md](docs/OBSERVATION.md) で
  API/Webhook のみ・デスクトップ記録なしと決め、見えない範囲の扱いまで書いた。
  対応する S0「観測範囲」画面は仕様（`config/product.json` の `backlog`）に置いてあるだけで、
  Figma にはまだ無い
- **S7 は参照画像の書き起こしで、コンポーネント未使用。** 他6画面がライブラリの
  Sidebar/Tag/Button/AxisMeter で組んであるのに対し、S7 はプリミティブで組んである。
  トークンは4系統とも100%束縛しているが、共通化はできていない
- **S7 のヒーロー背景は単色。** 参照画像は白→淡青のグラデーション。
  グラデーションは変数に束縛できないため、束縛率を優先して単色トークンにした
